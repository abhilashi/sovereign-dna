## 2024-05-24 - Accessible Interactive Cards Built with Non-Semantic Elements
**Learning:** When turning non-semantic HTML elements (like a generic `div` or a `motion.div`) into interactive, clickable components (e.g., conditionally making a `Card` component act as a button by passing an `onClick` prop), setting `cursor: pointer` is not enough for accessibility. The component becomes completely inaccessible to keyboard users and screen readers unless specific ARIA roles, tabindex, and keyboard event handlers are implemented.
**Action:** Always conditionally attach `role="button"`, `tabIndex={0}`, and an `onKeyDown` handler that triggers on both "Enter" and "Space" (ensuring to call `e.preventDefault()` for "Space" to prevent unwanted page scrolling) to components that are unexpectedly acting as buttons. Furthermore, include focus-visible styles (e.g., `focus:outline-none focus:border-accent`) to provide visual feedback for keyboard navigation. Do not expose `role`, `tabIndex`, or `onKeyDown` in the interface definition if they are strictly conditionally defined inside the component based on interactivity.
