## 2023-10-27 - Accessible Framer Motion Components
**Learning:** When adding keyboard accessibility attributes (e.g., `role`, `tabIndex`, `onKeyDown`) that are conditionally hardcoded inside a component (like when an `interactive` state is derived from `onClick`), these shouldn't be exposed in the component's Props interface as it creates a misleading API where passed values are shadowed. Additionally, standard HTML DOM attributes are natively accepted by `framer-motion` components like `motion.div`. If grouping them, they can be typed using `HTMLMotionProps<"div">`.
**Action:** Use `HTMLMotionProps<"div">` to strongly type the conditionally applied accessibility props and spread them onto the `motion.div`. Avoid exposing them in the component's interface unless the caller is meant to explicitly control them.
