## 2024-05-18 - Interactive Framer Motion Components Accessibility
**Learning:** When building custom interactive components using framer-motion's `motion.div` that require keyboard accessibility, defining a separate `interactiveProps` object of type `HTMLMotionProps<"div">` prevents type issues (such as `onDrag` conflicts when extending standard React HTML types) and keeps the JSX markup exceptionally clean. Using Tailwind classes like `focus:outline-none focus-visible:ring-1 focus-visible:ring-accent focus-visible:border-accent` provides ideal visual feedback strictly during keyboard navigation without intrusive rings during mouse clicks. It's critical to intercept Spacebar keydowns with `e.preventDefault()` to prevent unwanted page scrolling when mimicking a button press.
**Action:** Default to creating typed `interactiveProps` and spreading them onto generic tags like `div` or `motion.div` when turning them into interactive semantic elements. Include both 'Enter' and 'Space' handlers, call `preventDefault()` for 'Space', and apply `focus-visible` utility classes for accessible focus state handling.
