## 2024-08-02 - Conditionally Accessible Divs Without Prop Pollution
**Learning:** When making a non-semantic component (like a custom `Card` based on a `div` or `motion.div`) interactive via an `onClick` prop, adding hardcoded accessibility attributes (`role="button"`, `tabIndex={0}`, `onKeyDown`) directly inside the component can conflict with standard DOM types if we try to expose them in the component's interface. Users of the component might try to override them, leading to unexpected behavior, or the types might clash (like with `HTMLMotionProps`).
**Action:** Do not expose these a11y props in the component's public interface if they are strictly derived from the `onClick` presence. Instead, create a localized, strongly-typed props object (e.g., `HTMLMotionProps<"div">` for framer-motion) within the component body, populate it conditionally, and spread it onto the underlying element. This keeps the public API clean while guaranteeing keyboard accessibility.
