## 2026-07-04 - Accessible Custom Buttons Must Exclude Hardcoded HTML Attributes from Props

**Learning:** When building custom interactive components using non-semantic elements (like a `div` acting as a `Card`), adding accessibility attributes (`role="button"`, `tabIndex={0}`, `onKeyDown`) conditionally based on a prop (like `onClick`) is necessary for accessibility. However, exposing these hardcoded HTML attributes in the component's TypeScript `Props` interface creates a misleading API. For example, if a developer tries to pass a custom `onKeyDown` to the `Card`, it will be silently ignored because the component's internal logic strictly hardcodes the `onKeyDown` for 'Enter' and 'Space' when interactive. This can lead to confusing bugs for developers consuming the design system.

**Action:** Only define HTML attributes in the `Props` interface if the component actually forwards or allows the caller to control them. If an attribute is strictly managed internally by the component (like `role="button"` when `interactive` is true), do not extend general HTML prop interfaces or explicitly list them in the component's custom interface. Ensure internal event handlers are properly typed using `react`'s event types (e.g., `KeyboardEvent<HTMLDivElement>`) to satisfy TypeScript without needing to expose them to consumers.
