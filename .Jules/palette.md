
## 2024-07-01 - Interactive Div Accessibility Constraints
**Learning:** When making non-semantic `<div/>` elements (like `Card`) interactive via `onClick`, adding `role="button"`, `tabIndex={0}`, and an `onKeyDown` handler is crucial for keyboard accessibility. However, exposing these raw accessibility props directly in the component's `Props` interface (e.g., `interface CardProps { role?: string }`) can create a misleading API where passed values are overshadowed by the component's internal logic that toggles them based on the `interactive` flag. Instead, the component should internally manage these accessibility attributes derived from the presence of `onClick`, and only expose them if it truly allows the parent to override its base semantic behavior.
**Action:** When adding accessibility attributes to custom interactive components, derive them internally based on the interactive state rather than exposing them as optional props, unless the component explicitly needs to support role/tabIndex overrides.
