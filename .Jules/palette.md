## 2025-02-28 - Adding Accessibility Attributes to Conditionally Interactive Components
**Learning:** When adding accessibility HTML attributes (e.g., `role`, `tabIndex`, `onKeyDown`) to components that become interactive conditionally based on the presence of an `onClick` prop (such as a standard Card wrapper), exposing these a11y props in the component's TypeScript interface creates a misleading API. The consumer cannot override them because they are hardcoded inside the wrapper based on interactivity. Additionally, `framer-motion`'s `motion.div` gracefully accepts standard HTML DOM attributes without explicit prop definition mappings in custom wrappers.
**Action:** Do not expose hardcoded standard accessibility props (like `role="button"` or `tabIndex={0}`) in the Component's Props interface if they are meant to be strictly derived from other states (like `interactive`). Let them be applied natively to the rendered element directly.
