## 2024-05-24 - [Card Component Interactive Accessibility]
**Learning:** Found that custom `Card` components, when made interactive via an `onClick` prop, lacked proper accessibility attributes (`role="button"`, `tabIndex=0`, `onKeyDown` handlers for Enter/Space) and visible focus indicators, making them inaccessible to keyboard users and screen readers. When using `framer-motion`, conditionally applying these multiple props can clutter JSX.
**Action:** When a generic wrapper like `motion.div` is conditionally interactive, compute a grouping object (e.g. `const interactiveProps: HTMLMotionProps<"div">`) with the `role`, `tabIndex`, and `onKeyDown` logic (including `e.preventDefault()` for Space) and spread it (`{...interactiveProps}`). Add clear focus styles using Tailwind utilities like `focus-visible:ring-1 focus-visible:ring-accent focus:outline-none`. Do not expose these a11y props on the component's public interface if they are strictly derived from another prop (like `onClick`).
