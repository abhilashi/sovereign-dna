## 2024-05-24 - Interactive Non-semantic Elements with framer-motion
**Learning:** When adding interactiveness to `framer-motion` non-semantic components (like `motion.div`), they can natively accept accessibility DOM attributes (like `role`, `tabIndex`, `onKeyDown`). However, if these attributes depend on conditionals (e.g. `const interactive = !!onClick`), it's cleanest to package them as an `HTMLMotionProps<"div">` object and spread them conditionally into the element: `<motion.div {...interactiveProps} >`. Also, be sure to provide focus indicators using `focus-visible:ring-1 focus-visible:ring-accent focus:outline-none`. Do not expose these inner accessibility props through the component's public interface if they are strictly derived from inner state or `onClick`.
**Action:** When making custom components built on `div` interactive, package all accessibility props into a correctly typed object (like `HTMLMotionProps<"div">`) and spread it to avoid cluttering JSX. Always manage keyboard support (`Enter` and `Space`) preventing scrolling on `Space`.
