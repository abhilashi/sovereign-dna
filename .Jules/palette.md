## 2023-10-27 - [Interactive Card Accessibility]
**Learning:** When adding accessibility attributes (e.g., `role`, `tabIndex`, `onKeyDown`) that are conditionally hardcoded inside a component (like when an `interactive` state is derived from `onClick`), do not expose these properties in the component's Props interface. Exposing them creates a misleading API where passed values are shadowed/overridden. Only define them in the interface if the component actually allows the caller to control them. Additionally, group accessibility props applied to `framer-motion` elements into a typed `HTMLMotionProps<"div">` object to prevent `onDrag` type conflicts and keep the JSX markup clean.
**Action:** When building custom interactive components using non-semantic HTML elements, ensure accessibility by providing `role="button"`, `tabIndex={0}`, an `onKeyDown` handler for 'Enter' and 'Space' (including `e.preventDefault()` for 'Space' to prevent page scrolling). Group them using `HTMLMotionProps<"div">` and spread them conditionally.
